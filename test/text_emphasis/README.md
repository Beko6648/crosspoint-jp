## 自動テスト

`py -3 test/run_text_emphasis_test.py --compiler <C++コンパイラのパス>`

本番のCSS parser、CSS cache serializer/deserializer、圏点の描画処理を使い、
ストレージ・フォント・フレームバッファのみをホスト用stubへ置き換える。
CSSの6綴り、入れ子解除用のスタイル上書き、キャッシュ往復・全切断位置での破損検出・旧版拒否、
指定glyph・代替glyph・幾何学的な円、52文字、句読点除外、フォント変更、ルビOFF、事前走査中の描画抑止を確認する。

## 実機の合格条件

1. 書籍スタイルを有効にし、縦書き・横書きそれぞれを開く。
2. 全10種類の点に欠けがなく、filled/openの違いが分かる。
3. `none`の区間だけ消え、その後の親指定が復帰する。次の段落・章へ指定が漏れない。
4. ルビON/OFFの両方で圏点が残る。併用時は本文・圏点・ルビが重ならない。
5. 句読点・空白・結合濁点・異体字セレクタに単独の点が付かない。反復記号「々」は文字として扱う。
6. 縦中横と横倒し欧文の各トークンは1点。横書き欧文は字幅に応じて各文字に付く。
7. 長い強調区間・改行・改ページ・前後ページへの往復でも欠落しない。
8. Noto、BIZ UD、Zen Maru Gothic等の利用可能なフォントで比較する。
   胡麻点がない場合は•/◦、その記号もない場合は円を描く。
   普通のフォントだけでは全fallback分岐が通るとは限らないため、欠落分岐はホスト試験でも確認する。
9. 最小余白、異なる文字サイズと行間、明暗表示、画像を含む別の本で既存表示を確認する。
10. 本を閉じて開き直し、キャッシュから表示した結果が初回と一致する。フォント変更で字形を再評価する。
11. X3/X4でキャッシュ生成完了、最小空きheap、最大連続空き領域、ページ端の欠けを確認する。

## 保存形式と対応範囲

- CSS cache version 8、Section version 102。旧キャッシュは通常のversion検証で再生成される。
- 圏点はルビと独立した1byteのトークン属性。圏点がないブロックには配列を保存しない。
- 指定glyphのbitmapを最大8x8へ縮小し、未収録・空bitmap時に点、最後に円へ代替する。
- 標準位置（縦書きの右、横書きの上）を対象とする。`text-emphasis-position`、任意文字の圏点、
  CSS色の再現は対象外。短縮形のblack/currentColor/red/blue/16進色は形の解釈を妨げない。
- 表のセルは既存のプレーンテキスト化経路を維持しており、セル内の圏点は対象外。
- ルビの手動位置調整を大きく動かした場合の干渉は実機確認が必要。
- 本変更だけではリリース番号を上げない。実機試験前の開発版であり、公開・書き込みは別作業。
