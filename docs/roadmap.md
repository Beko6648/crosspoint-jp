# CrossPoint Yomuka / v0.3.0 ロードマップ

更新日: 2026-07-31
基準: `xtc-large-file-fix` / `v0.2.9.0`

## 現在地

v0.2.9.0 では、読書画面の品質・キャッシュの安全性・日常操作を一通り改善した。v0.3.0 は機能を広げる版ではなく、読書品質の回帰確認、名称と案内の整理、配布までを確実に行うリリースとする。

### v0.2.9.0 までに完了した主な項目

- EPUB の縦書き、ルビ、縦中横、書籍スタイル3モード、TXT横書き、XTCの読了位置復帰。
- EPUBキャッシュの状態表示、中断・再開、書籍単位のキャッシュ削除、画像キャッシュの検証と再生成。
- スクリーンショット保存、キャッシュ生成中のキャンセルと撮影、SDカードからのファームウェア更新。
- 青空文庫のダウンロード、更新、索引の原子的保存、検証、再試行、HTTPS時のメモリ対策。
- EPUBしおり、Aozora履歴の保存、低ビット深度PNG対応、キャッシュ生成時のメモリ断片化対策。
- 縦書きの全角 `＜＞`、既存の括弧類、1桁・2桁半角数字の配置を修正。Noto系とBIZUDで実機確認済み。

### 継続して守ること

- キャッシュと読書進捗を壊さない。`/.full_cache_complete` がないキャッシュは中断済み・再開可能として扱う。
- 表示、入力、キャッシュ、ネットワークに触れる変更は、ビルドだけでなく対象端末で確認する。
- Flash/RAMの削減は、実測で必要性を確認してから行う。機能を先に削らない。
- `serial.txt`、`font_src/`、コードポイント作業ファイルは通常のファームウェア変更・リリース対象に含めない。
- `freeink-sdk` を更新するときはSDK側を独立してコミットし、取得可能な参照先、ファームウェア側のサブモジュール参照、X3/X4の回帰を一組で確認する。

## v0.3.0 の目標

**読書表示が安定しており、利用者が迷わず更新・利用できる状態にする。**

### 最優先: リリース前に固定すること

1. **名称を統一する**
   v0.3.0の正式名称は `CrossPoint Yomuka`、短縮表記は `Yomuka` とする。README、画面、Web Flasher、リリースノート、GitHubの案内をこの表記に統一する。
2. **リリース範囲を固定する**
   v0.3.0では表示品質、操作性、既存機能の検証を優先する。実機確認済みのX3向け表示・スリープ・設定画面改善は含めるが、追加の波形実験、開発者オプション、WebUIの大規模拡張は含めない。

### v0.3.0へ含めるX3対応

- 通常画面の高速更新LUTを調整し、ホーム・設定画面でカーソル移動を続けた場合の残像を許容範囲まで軽減する。
- スリープ表示専用の更新処理とパネル電源断手順を追加し、ホーム画面・通常EPUBからの手動／自然スリープで直前画面が浮き出る現象を改善する。
- XTCHのグレースケール基底処理を追加し、グレースケール表示後の画面更新を安定させる。
- EPUBのグレースケール画像ページ後に一度クリーンな更新を行い、次ページへ残像を持ち越しにくくする。
- X3設定画面の左右余白と選択カーソルを調整し、RTC設定を独立タブから「本体」へ統合する。
- XTCH表示後にスリープすると、数分後に直前画面が薄く浮かぶ場合がある。長い白消去は操作性への影響が大きいため採用せず、v0.3.0では既知の制限として案内する。

### リリース候補までの必須作業

1. **読書表示の実機回帰**
   - EPUB: 縦書き・横書き、ルビ、半角/全角数字、英字、`＜＞《》〈〉【】〔〕［］（）｛｝`、書籍スタイル3モード。
   - フォント: 少なくともNoto系とBIZUDで、半角数字の縦中横を確認する。
   - コンテンツ: 青空文庫EPUB、画像付きEPUB、長大EPUB、TXT、XTC。
2. **キャッシュと操作の実機回帰**
   - 未生成→生成中断→再開→完了、書籍単位削除後の再生成、読書進捗・しおり保持。
   - スクリーンショットの保存先・連番・失敗通知、キャッシュ生成中のキャンセル操作。
3. **X3の実機回帰**
   - クラシック／Lyraの設定画面で、サイドボタン表示、一覧文字、値、選択カーソル、ビルド番号が重ならない。
   - ホーム、設定、通常EPUB、画像付きEPUB、XTCHでページ更新速度と残像を確認する。
   - ホーム、通常EPUB、XTCHから手動スリープと自然スリープを行い、5分以上放置して表示状態を確認する。
   - ジャイロ、前面ボタン、サイドボタン、RTC有効／無効時のスリープと復帰を確認する。
4. **配布・更新経路の確認**
   - SDカード更新を実際に書き込み、再起動まで確認する。
   - README、基本操作ガイド、Web Flasher、GitHub About、リリースノートの `CrossPoint Yomuka` / `Yomuka` 表記と配布ファイル名をそろえる。
5. **リリース作業**
   - Flash/RAMの最終記録、`default` と配布用ターゲットのビルド、差分検査。
   - タグ境界と変更一覧を確認し、未コミットの作業ファイルをリリース対象から除外する。

### v0.3.0 の完了条件

- Noto系・BIZUDで、縦書きの半角数字と全角記号が意図どおりに表示される。
- 横書き・縦書き・ルビ・画像付きEPUB・TXT・XTCを代表作品で確認済み。
- キャッシュ生成、中断、再開、書籍単位削除、しおり、スクリーンショットが端末で動作する。
- X3の通常操作とホーム／通常EPUBからのスリープで、残像が日常利用上の許容範囲に収まる。
- X3のXTCH表示後に残る可能性がある薄いスリープ残像を、既知の制限としてリリースノートに記載する。
- SDカード更新で導入でき、更新後も既存の設定と読書データを安全に扱える。
- 名称、案内文、配布物、バージョン、リリースノートが一致する。

## v0.3.1 — 開発者オプション

### 目的

一般利用の設定を複雑にせず、実機で発生した表示、入力、スリープ、メモリ、キャッシュの問題を端末単体で切り分けられるようにする。設定値の変更より、状態確認、再現試験、診断情報の保存を優先する。

### 第1段階: 読み取り中心の診断

1. **デバイス情報**
   - X3／X4判定、ファームウェア版、ビルド番号、SDKコミット。
   - 空きヒープ、最大連続確保領域、SDカード容量。
   - RTC、ジャイロ、ディスプレイの検出状態。
2. **入力診断**
   - 前面、サイド、電源ボタンの押下状態を画面に表示する。
   - ジャイロの現在値、傾き方向、ページ送り判定を表示する。
3. **表示診断**
   - 手動フルリフレッシュ、白→黒→白の消去試験。
   - 既存の4階調グレースケールテストを開発者オプションから起動する。
   - X3のスリープ残像確認用テストパターンと、直前に使用した更新方式を表示する。
4. **診断ログをSDへ保存**
   - 直近の内部ログ、再起動・クラッシュ理由、メモリ、SD、RTC、ジャイロ、パネル情報、主要設定をまとめる。
   - `/diagnostics/`へ日時付きテキストとして保存し、不具合報告へ添付できるようにする。
5. **スリープ診断**
   - 最後のスリープ開始理由、復帰理由、RTC使用状態、スリープ前の表示方式を確認できるようにする。
   - X3でパネル電源断処理が実行されたかを記録する。

### 第2段階: 安全な検査・復旧

- EPUB、TXT、XTCのキャッシュ状態と使用容量を表示する。
- キャッシュと索引の整合性を検査し、壊れた項目だけを再生成する。
- 青空文庫索引の検査と再構築を、元データと中断復旧情報を保持したまま実行する。
- 変更・削除を伴う処理には対象と影響を示す確認画面を設ける。

### 開発者オプションに入れないもの

- LUT、パネル電圧、表示コントローラーの生コマンドの直接編集。
- パネル種類の強制指定、更新波形や消去回数の常用設定。
- 任意ファイル削除、保護なしのキャッシュ全消去。
- 通常ビルドでの無制限なデバッグログ常時出力。

これらは専用の試験ビルドと実機検証で扱い、保存設定として一般端末へ残さない。

### v0.3.1の完了条件

- 開発者オプションを使用しなくても、通常利用時の画面構成と操作手順が変わらない。
- X3／X4でデバイス情報、入力診断、表示診断、スリープ診断を実機確認する。
- 診断ログをSDへ保存し、再起動後にPCで内容を読める。
- 診断画面を終了すると、一時的なテスト状態が解除され通常の表示・入力・省電力状態へ戻る。

## v0.3.2 以降へ回すもの

- X3のXTCHスリープ残像に対する追加波形調査と、純正FW・本家CrossPoint・派生FWとの同一個体比較。
- TXT縦書き、画像描画品質の全面刷新、EPUBの自動章分割。
- WebUIの大規模機能追加、設定のエクスポート／インポート。
- リカバリーモード、先読み、キャッシュ自動削除など、利用者要望と安全設計がそろっていない機能。

## 共通の出荷チェック

- `git diff --check`、対象ビルド、配布物の存在、バージョン表示を確認する。
- 端末で読書・表示・入力・キャッシュ・更新を確認する。
- SDK変更を含む場合は、SDKコミットが取得可能で、サブモジュール参照と実際のビルドが一致することを確認する。
- 変更対象だけをステージし、`serial.txt` と無関係な作業ツリー変更を含めない。
