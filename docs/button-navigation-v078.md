# ボタン一覧の一時確保削減 v1

## 実装
本家PR https://github.com/crosspoint-reader/crosspoint-reader/pull/3698 を参考に、ButtonNavigatorのButtonsをvectorからinitializer_listへ変更。方向一覧を返す関数にはstatic constexprの保存領域を設け、戻り値が一時配列を参照しないようにする。呼出側の波括弧リストは同期処理中だけ借用する。std::any_of用algorithmを明示includeする。

YomukaのDown+Right／Up+Left、500ms開始・500ms間隔の既定値、比較演算、短押し、release抑制、ページ送り、MappedInputManagerの方向変換は変更しない。std::functionの一般的な確保まで除去する変更ではない。Homeの確保順は次の別作業。

## ホスト検証
`py -3 test/run_button_navigation_test.py --compiler <Zigのパス>`
main基点e9a5989aの実ButtonNavigatorと変更版を同じテストで比較。MappedInputManagerと時計だけを置き換え、new呼出を計数する。待機中のonNext/onPreviousを100セット呼ぶと旧版400回、変更版0回。短押し、方向組合せ、長押し閾値、反復間隔、長押し後のrelease抑制、複数ボタン同時入力、空のボタン一覧、一覧端の循環を確認。物理ボタンの電気特性や実機の回転割当を証明するテストではない。

## X3から実機確認
`yomuka-button-navigation-v1.bin`を通常のSD更新で適用。特別なEPUBやキャッシュ削除は不要。普段の書籍を使い、シリアルログはいつものコマンドで開始する。

1. Home／ファイル一覧：上下の短押しを数回、長押しで連続移動、離すと停止すること。短押しで飛びすぎないこと。
2. 設定：項目移動、行間や文字サイズなどの値変更を短押し・長押しで確認。変更した設定は元へ戻す。
3. キーボード：検索など普段使う入力画面で左右移動・長押し移動を確認。送信や設定保存は不要で、中断してよい。
4. UIが横向きになる設定で左右両方向を確認し、縦向きでも上下反転を含む4方向でボタンと案内が以前どおり対応すること。今回新しい割当はない。
5. 普段の本を開き、数ページ読む。読書中メニューの移動とHomeへの帰還を確認する。

まずX3の1〜5とログを確認してからX4でも行う。通常INFO版なので各ボタンの成功回数はログに出ない。押し方・方向・選択位置・離した後の停止の目視報告が受入の中心。ログは再起動やエラーの有無を補助確認する。

## 制限
今回の一時確保削減がメモリ断片化や体感速度をどれだけ改善するかは未測定。以前報告された「日本語タイトル一覧を開いた直後の一瞬の操作待ち」を修正したとは扱わない。Home待機での実測回数は主ループの頻度に依存し、ホストの400回を実機の秒あたり回数と混同しない。
