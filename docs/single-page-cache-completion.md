# 本文1ページの完了表示 v1

## 変更範囲
通常読書で新規生成したキャッシュについて、全spineが1章、生成ページ数1、CSS準備が成功（埋込スタイル無効なら不要）、元のHTMLに画像等の要素なし、章の最終検証と保存が成功、ページ再読込が成功し画像なし、をすべて満たす場合だけ既存の全体完了markerを発行する。キャッシュ形式は変更しない。

元HTMLのimg/image/svg/object/embed/picture/audio/videoを隠し要素や表示設定のスキップより前に記録する。名前空間接頭辞も除いて判定する。画像抽出に失敗してplaceholderになった場合や、画像表示OFFで見えない場合を本文だけと誤認しない。

既存キャッシュには元HTMLの画像有無の証拠がないため、自動昇格しない。今回の新規4冊を用い、普段のキャッシュ全消去は不要。対象外の本について従来の本ごと／全書籍生成による完了は維持する。フォント変更等で複数ページになれば対象外となる。HTML非対応機能の完全性を保証する変更ではない。

## X3の確認
通常のSD更新でyomuka-single-page-cache-v1.binを適用し、4冊をSDへコピー。今までと同じシリアルログを開始する。最初の確認では本ごとのキャッシュ生成を選ばず、通常読書で開く。

1. 「完了表示v1・本文だけ」を開く。1ページであること、本文表示が正常なことを確認してHome→一覧へ戻る。アイコンが完了になること。もう一度開いて戻り、完了を保持すること。
2. 「完了表示v1・二章」を開き、第1章だけを表示してHome→一覧へ戻る。完了にしないこと（半円）。
3. 「完了表示v1・長文」を開き、先頭だけ表示してHome→一覧へ戻る。完了にしないこと（半円）。
4. 「完了表示v1・画像あり」を開き、本文と画像を確認してHome→一覧へ戻る。完了にしないこと（半円）。必要なら画像表示OFFでも、書籍別キャッシュのみ再生成して同じ結果を確認できる。
5. 最後に「長文」で従来の本ごとのキャッシュ生成を行い、完了表示になり、再実行が再生成せず終了することを確認する。

対象の本文だけが大きな文字設定で2ページ以上になった場合、半円が正しいのでページ数と設定を報告する。まずX3のログと1〜5の目視結果を確認し、その後X4へ進む。

## 診断と検証
成功時はERSのSingle-page text cache complete。書込失敗時はCould not publish single-page completion marker。画像/複数章/複数ページ/既存キャッシュではこの成功ログは出ない。通常版の先読みは維持し、library_profileの詳細ログは不要。

ホスト試験はtest/run_single_page_cache_test.py（--compilerにZig）で候補条件とメディア要素、生成完了前に証拠を公開しない順序を確認する。既存のincremental parser試験も実行する。SD書込と実画面での受入は別途X3/X4で行い、完了までコミットしない。
