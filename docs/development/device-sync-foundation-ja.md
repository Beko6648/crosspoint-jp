# 端末間読書データ共有の基礎

まずX3、X4、将来のX4 V2／Proで同じ本を確実に識別し、読書状態を安全に交換できる前提を固定します。クラウド同期や自動競合解決から始めず、端末内にある読書データを利用者が確認して受け渡せる手動同期を先に実装します。

## 現在ある基盤

EPUBはファイルパスではなく、ZIP中央ディレクトリから計算する64-bitの内容指紋で識別します。この値は`BookId`として、次のデータを`/.crosspoint/books/<source-fingerprint>/`に結び付けます。

- `progress.bin`：章番号、章内ページ、章ページ数、完読状態
- `bookmarks.json`：しおり
- `book-reader-settings.json`：本ごとの表示設定
- 読書履歴：読書時間、最終読書日時、完読日時

本を移動・改名しても同じ内容なら読書状態を維持できます。同じパスのEPUBを更新した場合は、旧指紋を記録して必要な読書データを引き継ぎます。

## 同期データの最小単位

将来のエクスポート／インポートは、EPUB本体や表示キャッシュを含めず、1冊につき次をJSONで交換します。

```json
{
  "formatVersion": 1,
  "bookId": "0123456789abcdef",
  "progress": {
    "spineIndex": 12,
    "chapterPage": 34,
    "chapterPageCount": 120,
    "finished": false
  },
  "updatedAt": 0
}
```

- `bookId`が一致する本だけに適用する
- `updatedAt`はRTCまたはNTPで時刻が得られるときだけ使う。時刻が不明な端末は`0`のままにする
- 位置はページ番号だけでなく、章番号と章内総ページ数を併記する。端末ごとのフォント・余白が異なるとページ数が変わるため、完全な位置一致は保証しない
- キャッシュ、Wi-Fi設定、端末設定、EPUB本体は同期対象にしない

## 競合時の方針

最初の実装では、同じ`bookId`で両方に記録がある場合、時刻が有効なら新しい`updatedAt`を採用します。時刻が比較できない場合は自動で上書きせず、端末側で「この端末の位置を使う」か「受け取った位置を使う」かを選びます。

しおり、本ごとの表示設定、読書履歴は読書位置と別の同期単位にします。位置同期が成功しても、設定や履歴を意図せず上書きしません。

## 導入順

1. **v0.7.4（完了）**：内容指紋を使う保存基盤を導入した。同期用UIや通信は追加しない。
2. **v0.7.7**：診断、安定性、Landscape UIを優先する。読書データ共有の機能追加は行わない。
3. **v0.7.8**：読書レスポンスやキャッシュ性能を改善する。同期データの入出力はまだ追加しない。
4. **v0.8.0**：X4 V2／Proを含む端末共通基盤を整理し、`BookId`、同期スナップショットの形式、各データの更新日時と互換性規則を確定する。X3/X4で同じ本を同じ`BookId`として扱えることを確認する。
5. **v0.8.1**：SDカードまたはWebUIで読み書きできる手動同期スナップショットを追加する。取り込み前に対象の本と差分を表示し、読書位置、しおり、本ごとの表示設定、読書履歴を個別に選べるようにする。異なる書字方向・フォントでの位置復元をX3/X4で確認する。
6. **v0.8.2以降**：競合処理を改善し、必要性と安全な認証情報の扱いを確認した後に、外部サービスを使う自動同期を検討する。

この順序なら、X4 V2／Proの追加によって同期データ形式を分岐させずに済みます。また、位置同期の導入だけで、しおりや本ごとの設定、履歴が意図せず上書きされることを防げます。

## v0.8.1の最初の範囲

- 端末Aで同期スナップショットを書き出す
- SDカードまたはWebUIで端末Bへ渡す
- 端末Bに同じ`BookId`の本がある場合だけ取り込み候補にする
- 自動適用せず、対象の本、更新日時、取り込むデータ種別を画面で確認する
- 時刻を比較できない場合は、端末側のデータと受け取ったデータのどちらを使うか選択する
- EPUB本体、表示キャッシュ、Wi-Fi設定、端末全体の設定は含めない
