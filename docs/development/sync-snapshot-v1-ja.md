# 読書データ同期スナップショット v1

v0.8.0で確定する交換仕様。読書位置、しおり、本ごとの表示設定、読書履歴の4種類を対象とする。入出力・通信・取り込み画面・更新日時の保存はv0.8.1で実装する。本書だけで現行ファームウェアが同期可能になるわけではない。

機械可読定義は[snapshot-v1.schema.json](sync/snapshot-v1.schema.json)、4種類を含む例は[all-units.example.json](sync/all-units.example.json)。以前の基礎文書にあった最小JSONは未実装の草案であり、この形式に置き換える。

## 外枠と互換性

- 1ファイル1冊。UTF-8、BOMなし、最大65,536バイト。重複キー、NaN、Infinity、未知のキー、未知のバージョンは拒否する。暗黙の切り詰め・数値変換はしない。
- `format`は`yomuka-book-snapshot`、`formatVersion`は整数`1`。
- `bookId`は小文字16桁の16進文字列。JSON数値にしない。ゼロは識別不能として交換不可。
- `exportedAt`はUTC Unix秒（0〜4,294,967,295）、時計不明なら0。書き出し日時であり新旧判定には使わない。
- `units`は`progress`、`bookmarks`、`readerSettings`、`history`のうち1〜4種類。各種類は必須の`updatedAt`と`data`を持つ。
- 種類の省略は「触らない」。`null`を種類の削除指示として使わない。各種類は個別選択できるが、選択した種類の内部は全体置換とする。
- v1の項目・意味は固定する。項目追加や意味変更は新バージョンとし、旧端末はファイル全体を拒否する。未知の種類だけ黙って捨てない。
- パス、EPUB本体、キャッシュ、フォントファイル、Wi-Fi認証情報、端末全体の設定、最近開いた本の一覧は含めない。

## BookIdの一致

現行`ZipFile::getArchiveFingerprint()`と同じFNV-1a 64-bit。初期値14695981039346656037、各バイトについてXOR後1099511628211を掛け、64-bitに丸める。入力は順番に、ZIPファイル長のuint64LE、中央ディレクトリ位置のuint32LE、中央ディレクトリ長のuint32LE、エントリ数のuint16LE、中央ディレクトリの生バイト。

改名・移動だけでは変化しないが、再圧縮、ZIP内の日時や順序の変更でも変わり得る。本文の意味的な同一性や改ざん耐性を保証するハッシュではない。受信側で同じBookIdのEPUBを解決できる場合だけ候補とし、タイトルやパスで代用しない。複数パスなら利用者が対象を選ぶ。既存の旧ID移行用パス索引は交換せず、ID不一致時の自動移行も行わない。

## 更新したEPUBの扱い

同一パスの本を更新し、端末内の既存処理で新BookIdへの引き継ぎを行った後なら、新BookIdのスナップショットを書き出せる。受信側にも同じ更新版EPUBが必要。更新前に書き出した旧BookIdのファイルは引き続き不一致となる。送受信側のどちらでも、EPUBを開いて新しい位置・しおり・設定を確認してから利用する。

現行`ReaderActivity::loadEpub()`は同一パスの旧IDを検出し、`BookDataPath::migrateArchiveData()`、`BookReaderSettings::migrate()`、ID記録、`ReadingHistoryStore::migrateBookId()`の順に処理する。位置・しおり・設定は新ID側に既存データがあればそれを保持する。履歴は旧IDを付け替え、重複項目の時間・回数を加算する。この既存動作は今回変更せず、同期の全体置換とは区別する。

引き継ぎは本文の対応位置を探索せず、複数保存先をまとめたトランザクションでもない。履歴移行は保存成功を呼び出し元へ返さないため、移行ログだけで4種類すべての保存完了を保証しない。将来の書き出し処理は保存完了・読み戻しを確認し、移行途中や読み取り失敗を空のデータとして書き出さない。

章構成変更後の位置は利用者の確認が必要。新EPUBの章範囲を外れた位置・しおりは黙って補正して書き出さず、当該種類を除外して理由を表示する。旧IDと新IDの対応記録を端末間で交換する機能、本文アンカーによる復元、更新前のデータを更新版へ直接取り込む機能はv1に含めない。これらは手動同期の完成後に別バージョンとして検討する。

## 既存保存データとの変換境界

| 種類 | 読み出し元 | 変換時の規則 |
|---|---|---|
| progress | 新BookId配下のprogress.bin | ファイル全長を確認して4/6/7/8バイトを区別。7バイトまでしか読まない既存ヘルパーでは8バイト目の進捗を取得できない |
| bookmarks | 新BookId配下のbookmarks.json | 全件を検査してから24件上限を確認。既存ローダーの切り詰めを成功扱いしない |
| readerSettings | 集約JSONのbooks内の新BookId項目 | 保存された項目だけ変換。実効設定のcaptureAllで全体設定を混ぜない |
| history | 履歴ストア内の新BookIdの本別項目 | 読書セッションの未保存分を確定してから取得。移行用の加算処理を同期時に呼ばない |

読書位置・履歴が存在しなければその種類を省略する。しおりが存在しない場合は正常な未作成と確認できたときだけ空配列、本固有設定が存在しなければ正常な未作成と確認できたときだけ空オブジェクトに変換できる。ストレージ未準備、破損、アクセス失敗は「存在しない」と区別し、書き出しを中止する。識別不能なTXT/XTCをEPUBとして交換しない。

設定の整数enum→文字列、0/1→boolean、ルビオフセットのバイアス除去は下表に従う。型・値域を検証してから変換し、未知値を既定値に丸めない。変換後もスキーマと項目間制約を再検証する。読み出しだけで現行保存ファイルを書き換えない。

## 更新日時

各`updatedAt`は、その種類を最後に変更したときのUTC Unix秒。未記録または時計不明は0。**現行保存データの4種類はいずれも更新日時を持たないので、初回の変換では全て0**とする。書き出し日時、FAT更新日時、履歴の`lastReadAt`を代用しない。

v0.8.1では、時計が有効な変更時だけ種類ごとに記録する。時計不明の変更では古い日時を残さず0にする。取り込み時は受信した日時を保持し、現在時刻へ置換しない。日時が双方で有効でも時計ずれを否定できないため、新しい方は推薦に留め、必ず差分と選択を確認する。0や同時刻の競合を自動解決しない。現時点では日時用の永続領域を追加しない。

## 読書位置 `progress`

| 項目 | 値 |
|---|---|
| spineIndex | 0始まりの章番号、0〜65535 |
| chapterPage | 0始まりの章内ページ、0〜65535 |
| chapterPageCount | 章ページ数0〜65535、古い記録で不明ならnull |
| finished | 完読フラグtrue/false、古い記録で不明ならnull |
| percent | 本全体の整数進捗0〜100、不明ならnull |

全項目必須。不明をfalseや0へ捏造しない。ページ数が正なら`chapterPage < chapterPageCount`。0ならページも0。不明の場合は受信側の再計算で範囲確認する。

受信側EPUBのspine数をNとすると通常は`spineIndex < N`。終端表現は`spineIndex == N`、ページ0、ページ数0、finished=true、percent=100のみ許可。N超過は拒否する。現行の完読フラグは95%以上でも立つので、finished=trueだけで終端へ移動させない。

旧`progress.bin`の4/6/7/8バイトは先頭からuint16LEの章・ページ・ページ数、1バイトの完読、1バイトの進捗。4バイトなら後3項目null、6バイトなら後2項目null、7バイトならpercent=null。8バイトの進捗不明値255はnull、範囲外の破損値は拒否する。非対応の長さは推測しない。

位置は近似でありCFIや文字アンカーではない。章ページ数が変化した場合、旧ページ数が正なら`floor(旧ページ / 旧ページ数 × 新ページ数)`を新章の範囲に収める。不明なら旧ページ番号を範囲に収める。章の再計算後に復元し、同時に設定を取り込む場合は設定を反映してから計算する。不明な完読・進捗は受信側が再計算し、現行保存形式への変換規則を実装時にテストする。

## しおり `bookmarks`

`data`は0〜24件の配列。各要素は章・ページ・ページ数（正の整数）、`summary`（最大512文字）、`progressRatio`（0〜1の数値）を全て持つ。ページはページ数未満。同一の章・ページが重複した配列は拒否する。章番号は対象EPUBの範囲内。順序は保持する。

現行`percentage`は0〜100でなく0〜1なので、交換名を`progressRatio`とする。保存キー`spine/pages/page`は交換時に`spineIndex/chapterPageCount/chapterPage`へ変換する。summaryは表示用テキストで、命令やパスとして扱わない。

しおりID・削除履歴は現行にないため、個別マージを行わない。選択した配列で全しおりを置換し、空配列は全削除として確認画面に明示する。再取り込みでしおりは増えない。異なるレイアウトで選択したしおりへ移動する位置も近似となる。

## 本ごとの表示設定 `readerSettings`

`data`は本固有の上書き項目だけを持つオブジェクト。全体設定から補った実効値を勝手に含めない。選択時は上書き項目集合を全体置換し、省略項目は**受信側の全体設定を継承**する。空オブジェクトは本固有設定の解除。horizontal/verticalの空オブジェクトも上書きなしを意味する。

内部enum番号を交換せず、下記の文字列へ明示変換する。括弧内は現在の保存値。

| 項目 | 交換値 |
|---|---|
| writingMode | auto(0), horizontal(1), vertical(2) |
| orientation | portrait(0), landscape-cw(1), inverted(2), landscape-ccw(3) |
| bookStyle | crosspoint(0), epub(1), balanced(2) |
| imageRendering | display(0), placeholder(1), suppress(2) |
| invertImages | boolean（保存時0/1） |

horizontal/verticalは独立し、それぞれ次の項目を任意に持てる。

| 項目 | 交換値 |
|---|---|
| font | familyとsdFamilyNameを両方持つオブジェクト |
| font.family | noto-serif(0), noto-sans(1), open-dyslexic(2) |
| font.sdFamilyName | SDフォント名、空なら組み込み指定、最大31 UTF-8バイト |
| fontSize | small(0), medium(1), large(2), extra-large(3) |
| lineSpacing | 80〜220（%） |
| charSpacing | 0〜50 |
| paragraphAlignment | justified(0), left(1), center(2), right(3) |
| extraParagraphSpacing | 0〜4 |
| screenMargin | 5〜40 |
| firstLineIndent, rubyEnabled | boolean（保存時0/1） |
| rubyOffsetX, rubyOffsetY | -16〜64px（保存時は16を加える） |
| tateChuYokoMaxDigits | 2または3 |

全文字列でNULを拒否する。フォント名はファイルパスとして直接使わず、ローカルのフォント一覧から完全一致で解決する。SD名が非空ならそのフォントを要求する。同名でもファイルが異なれば組版は一致しない。旧組み込みfamilyの識別値は保持するが、現在の組み込み選択はnoto-sansのみ。受信側に要求フォントがない・旧組み込みが使えない場合は、設定種類全体を保留し、他の3種類だけ選択可能とする。黙って代替フォントに置き換えない。

hyphenationEnabledは現行本固有設定に保存されないため含めない。文字AA、UI向き、傾き、RTC、ボタン設定も含めない。

## 読書履歴 `history`

全項目必須：`seconds`（累計読書秒）、`sessionCount`（累計セッション数）、`lastReadAt`、`finishedAt`（UTC Unix秒）、`finished`（boolean）。整数は0〜4,294,967,295。日時0は未記録であり、finishedAt=0でも完読済みであり得る。日時の大小だけで破損と断定しない。

BookIdで特定した1冊の要約を全体置換する。秒数・回数を加算せず、maxによる擬似マージもしない。小さい値へ戻る場合も差分として明示して選択する。ゼロ値を揃えた要約の取り込みはその本の要約のリセットを意味し、省略と異なる。同じデータの再取り込みは同じ結果となる。進捗のfinishedとは別記録なので連動して上書きしない。

端末全体の`totalSeconds`と日別`days`は、現行では本との対応を持たず安全に合成できないため交換しない。タイトル・著者・パスは受信側EPUBから解決する。BookId不明の旧履歴はEPUBからIDを確定できるまで書き出せない。

v0.8.1の取り込みは本別要約だけを置換し、端末全体・日別累計は変更しない。このため本別秒数の合計と端末累計は一致しないことがある。履歴画面は「この端末の記録」と「取り込みを含む本別記録」を区別して表示することを実装の必須条件とする。セッション明細を持たないv1では、複数端末で読んだ時間の正確な合算は提供しない。

## 検証・適用順序（v0.8.1の実装条件）

1. サイズ・UTF-8・JSON・スキーマ・本書の項目間制約を検証。失敗時は一切書き込まない。
2. BookId、EPUBの章範囲、フォントの存在を確認。読み取り失敗を「空の設定・しおり」に変換しない。
3. 種類ごとの変更、解除、時刻不明、位置の近似、履歴の集計範囲を表示して選択を受ける。
4. 読書中の保存と競合しないよう閉じるか排他し、選択した全種類のバックアップと復旧記録を作る。途中失敗時に復旧可能な一時保存・差し替え方式を実装する。現在の保存APIを呼ぶだけでは複数ファイルの原子性は保証されない。
5. 設定を反映し、位置・しおりを再計算して復元。非選択種類、他の本、全体設定は変更しない。成功/失敗と種類を明示する。

ホスト検証：`python -m pip install -r test/requirements-sync-snapshot.txt`後、`python test/test_sync_snapshot.py`。スキーマと追加の静的制約を検証する参照テストであり、EPUB解決や実機インポートの実装ではない。

v0.8.1ではX3→X4とX4→X3で、4種類各単独・全部、改名した同一EPUB、再圧縮した不一致EPUB、フォント不足、異なる余白/方向、時計なし、空しおり・設定解除、同じ履歴の2回取り込み、保存途中失敗・再起動復旧を確認する。今回の仕様・テストだけの変更ではファームウェア再ビルドや実機再確認は不要。
