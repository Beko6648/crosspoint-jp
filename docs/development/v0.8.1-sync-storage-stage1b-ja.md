## 保存処理の監査と実装

| データ | 保存元と主な経路 | 今回の変更 |
|---|---|---|
| 読書位置 | 本ごとの progress.bin。EPUB終了・完読操作・旧形式移行 | 4/6/7/8バイトの完全読み取りAPI、保存結果、日時の永続化。移行時に8バイト目を落とさない |
| しおり | 本ごとの bookmarks.json。読書画面・しおり一覧 | 同期向け完全読み取り、上限24件と型・範囲検証、updatedAtを同じJSONへ保存 |
| 本固有設定 | /.crosspoint/book-reader-settings.json。設定保存・解除・BookId移行 | 保存済み項目だけを取得。全体設定の実効値は取り込まない。解除も日時付きで保存 |
| 読書履歴 | /.crosspoint/reading-history.json。セッション・完読・削除・移行 | flushPending/endSessionなどで保存成否を取得。失敗時は未保存変更を保持。削除した本の日時も保存 |

StorageIoの共通保存は、一時ファイルへの完全書き込み、close、長さと内容の再読み取り確認を行う。旧ファイルを.bakへ移してから公開し、公開失敗時は旧ファイルへ戻す。再起動後、通常ファイルがなければ.bakを復元する。通常ファイルが存在するときはそれを優先し、未確定の.tmpは読み込まない。保存全体に既存の再帰ストレージロックをかける。

読書位置の既存形式は変更せず、30バイトのprogress.bin.sync-timeを併用する。YSM1と、日時・長さ・元の位置バイト列を持つ2枠を保存する。新旧どちらの位置が残っても、それに一致する日時だけを返す。しおりはルート、本固有設定と履歴は本単位のupdatedAtを保存する。

日時のない旧データは0（不明）。時計が不明な変更も0。FAT日時や書き出し時刻を代用しない。同一内容の再保存は日時を更新しない。履歴の保存再試行では、再試行時刻ではなく変更時点の日時を使う。保存失敗では確定済みの日時を更新しない。

破損データと不存在を区別し、同期向けAPIは失敗時に出力値を変更しない。JSON読み取りは末尾の余分なデータも拒否する。しおりは64KiB、集約JSONは256KiBを上限にし、超過を切り詰めて上書きしない。

TXT/XTCの位置形式は維持し、共通の安全な保存とバックアップ復元のみ接続した。しおりUIの既存読み取りは互換性を維持し、同期専用の厳密な読み取りと区別している。

## 検証と残る範囲

default / gh_release / x4cのビルド成功。読書位置変換テスト35項目・892106チェック、既存snapshotテスト12項目が成功。追加の保存テストは、短い書き込み、読み取り・close・rename失敗、保存途中の状態からの再起動、日時との整合、解除・履歴再試行を検証する。実行結果の詳細は作業成果物の検証報告を参照。

この段階は保存基盤。同期ファイル全体の厳密検証（重複キーなど）、4種類まとめての適用・ロールバック、取り込み日時の実ファイルへの接続、SD/Web入出力と差分確認画面は次段階。各ファイルの復旧があっても、複数ファイルの一括更新を保証しない。

HALのflushは成否を返さないため、実際のSD内部への永続化や電源断をホストテストだけで保証できない。既存UIすべてへの保存失敗表示も今回完成していない。X4 ClassicはExperimentalのまま。
