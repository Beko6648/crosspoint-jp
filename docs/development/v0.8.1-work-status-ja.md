## 守る範囲

- 同一BookIdのEPUB、1ファイル1冊。種類を選んで全体置換し、無確認のマージをしない。
- BookIdの不一致をタイトルやファイル名で代用しない。
- 既存形式の互換性を維持し、実機で保存と復元を確認してから統合する。
- SDK更新、BLE、HAL全面再編、OTA/リカバリー刷新、TXT統合を混ぜない。
- X4CはExperimentalのまま。実機なしで対応済みに変更しない。
- 廃止済みの文字AAは復活させない。

## Issue #40の読み取り専用診断（2026-10-02、最初の診断版の記録）

この節は容量補正を追加する前の記録。最終的な容量補正・実機確認は後続の節を参照。

報告されたv0.7.8の83%→3%急落ログはfull_mAh=2872、remaining_mAh=86、voltage_mV=3544、current_mA=-50、valid=0xF。設計容量はまだ不明のため、ゲージ設定/学習値不一致の候補を確認する読み取り専用診断を追加した。容量補正・学習値書換え・Controlコマンド・リセットは行わない。

手動レポートにbattery_gauge_design_mAh、full_mAh、remaining_mAh、soc_percent、voltage_mV、current_mA、battery_status、operation_status、validマスクと取得時刻/所要時間を追加。OperationStatusからsecurity、cfgupdate、initcomp、edv2を出力。取得失敗はunknownとする。UI描画との競合を避けるためRenderLock内で順次読取り、原子的な同時スナップショットとはしていない。X4 ADC/S3では利用不可としてX3のレジスタを読まない。

急落/debugログに同じpoll_msのGAUGE_STATE行を追加。従来SOC_JUMPのvalidマスクは維持し、GAUGE_STATE側はdesign/BatteryStatus/OperationStatusの3ビットマスクを別に使用。ログの256バイト上限で情報が切れないように別行とした。ホスト3構成で読み取り・各レジスタ失敗/短縮読込み・SOCキャッシュ維持・ADC分離を検証済み。実機の診断レポート内容は確認待ち、未コミット。

参照: [TI BQ27220 TRM](https://www.ti.com/lit/ug/sluubd4a/sluubd4a.pdf) 2.7/2.21/2.27/2.28。[上流SDK PR #132](https://github.com/Free-Ink/freeink-sdk/pull/132)と[本家PR #3730](https://github.com/crosspoint-reader/crosspoint-reader/pull/3730)は容量補正候補で、今回の差分には適用していない。

診断版ビルド: default/gh_release成功（RAM49172、Flash4590001バイト）、x4c成功（RAM58880、Flash4481331バイト）。変更C++のclang-formatとgit diff --check成功。開発版の版表示はv0.8.0のまま。X3/X4実機確認、コミット、GitHubへの投稿は未実施。
