# v0.8.0 全差分レビュー

実施日: 2026-09-28。基点`2a03c4b6`（v0.7.8）、対象`1f770843`。親リポジトリ43ファイルと、SDKの`bc31e96`→`18e73e16a1965fb19c62fa3a717cbc3a5b43add3`差分を確認した。作業一覧・ロードマップの未コミット変更は保持した。

## 判断

確認した差分とhost検証の範囲では、新規のリリース阻害不具合は見つからなかった。製品コードへの追加修正は行っていない。最終ビルド・実機確認へ進めるが、公開承認や全ハードウェアでの動作保証ではない。

## 確認内容

| 領域 | 結果 |
|---|---|
| SDK固定 | submoduleのHEADと表示revisionが一致。SDK mainへの更新なし |
| X3 IMU | HalTiltSensorの差分なし。SDKの両X3 profileでswap/flipはfalse、既存軸mappingを維持 |
| X4C検出 | NVS優先、未設定時VER probe。未知VERはUC8279へfallback。診断は保存されたprobe結果を使い、表示バスを再probeしない |
| 電源・診断 | abort情報を一度取得してRAM保持。通常起動ではabortのINFOログなし。X4CはCW2017を使い、GPIO0をC3の電池ADCとして読まない |
| SD更新・Recovery | Yomuka独自処理は変更なし。SDK内のRecoveryBoot変更はlib_depsに追加されていない |
| 描画ロック | TryLock失敗時は保護対象へのアクセスを避ける。取得失敗時のunlockなし。電源方針の呼び出しはロック解放後 |
| Web終了 | メインループで取得したBack入力を先に確認し、通信処理中は各handleClient後に確認。20msはバッチの上限であり、1件の同期通信を中断する期限ではない |
| 縦書き字形 | 総空き32KBの条件と各nothrow割当失敗処理を維持し、固定の最大連続32KB条件だけを除去。確保失敗・読み込み不足の解放経路を確認 |
| 自動ページ送り | 日本語表記を秒間隔へ変更。選択値と時間計算は変更なし |
| 保存形式 | 既存の読書位置、しおり、本固有設定、履歴の製品保存処理に変更なし。同期仕様・参照テストは実データを読み書きしない |
| CI | 3環境のビルドとhost jobをTest Statusへ接続。同期仕様テストは現在このjobに含まれず、リリース前に別途実行が必要 |

SDK内のUC8179/UC8279 X4系グレースケール変更は、通常X4のSSD1677およびX3用driverと別経路。X4Cでは実表示・波形品質をhostだけで保証できないためExperimentalを維持する。

- hardware/reader/SDK host回帰: **13スイート成功**。battery diagnostics、SDK Stage 1、X4C診断、render scheduling、Web exit、vertical glyph load、chapter input lock、idle image、chapter incremental、chapter exit、SDK pro/uc8279/uc8253 power。
- 同期形式参照テスト: **12件成功**。

- v0.7.8からのgit diff --check: 成功。
- SDK作業ツリー: 変更なし。

hostテストには製品ソースを抜き出してstubで実行するものが含まれる。実際のFreeRTOS競合、Wi-Fi通信、電源断、E-Ink表示の完全な再現ではない。GUI simulator、ファームウェアの再ビルド、GitHub CI、実機操作はこのレビュー中には実行していない。以前の3環境ビルド・実機結果と今回の検証を混同しない。

## 残る制限

1. 初回Webフリーズと最初の句読点異常の原因は未確定。同期handleClientの待ち時間は残るため、実際の転送と本体終了を最終候補で確認する。
2. SDK deep-sleep abort記録は取得可能なAPIを追加しているが、IDFのnoreturn経路により実際のabort復旧効果は保証できない。今回のレビューで解決扱いに変更しない。
3. X4C実機、X4 GPIO13電気測定、X3傾き方向/OFF、SD更新の実書込みは既存記録の未確認項目として保持する。
4. 同期仕様は型・範囲と静的な制約を検証する参照基盤。フォントの実在、EPUB解決、変換後の実機保存、複数ファイルの復旧はv0.8.1の実装条件である。

次は[作業一覧](v0.8.0-work-status-ja.md)に沿い、バージョンとbuild IDを確定した最終候補のビルド、サイズ・チェックサム記録、短い実機回帰を行う。
