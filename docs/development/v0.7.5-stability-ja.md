## 1. OOM防御の第1段階

参考: [reader-mod fa4a55b2514ceaf47187546a993dc771c186e832](https://github.com/osakanataro/crosspoint-reader-mod/commit/fa4a55b2514ceaf47187546a993dc771c186e832)。同コミットは行/列の一時領域をnothrowで試しに確保して解放し、その後のSTL確保に進む方式。フォントキャッシュ保持量の変更は今回取り込んでいない。

### 実装

- `LayoutMemory.h`: 加算・乗算の飽和処理、free heap/最大連続領域の確認、4KiBの余裕を含むnothrow試行確保。失敗ログは`PTX Layout stopped: <段階> need=... free=... largest=...`。
- `ParsedText`: 段落の幅/高さ/禁則用配列、SDフォントprewarm文字列、ruby高さ、行列境界、字下げ、soft hyphen用文字列、ハイフネーション、縦書きの長いSideways分割に事前検査を追加。prewarm後にも再検査する。
- 行/列の`prepareBlock()`は本文・rubyの文字列本体、style、X/Y座標、圏点、sparse画像とパス、TextBlock/共有所有権の領域を見積もる。TextBlock本体はnothrowで生成。配列を先に用意し、1行/列分をコピーするため、元のwords/ruby/画像は成功が確定するまで変更しない。
- ページへのコールバックをboolにし、ページが拒否した行/列は消費しない。成功した接頭部分だけを`consumePrefix()`でwordsと並列メタデータ、画像情報から一緒に削除する。後続の行で失敗しても、成功済み部分の消費は正確に反映する。
- `layoutFailed()`は失敗後も保持する。同じParsedTextを続行せず、パーサの`lowMemoryAbortRequested`へ伝える。メモリ都合の途中flush、通常段落、捨てる空行、末尾flushを確認し、失敗後の後続コールバックと成功終了を抑止した。
- パーサは初回Page生成とTextBlock受理後のPageLine/要素配列/脚注領域も検査する。既存のSection失敗経路が一時セクションファイルを閉じて削除し、完成キャッシュへ昇格させないことをコードで確認した。
- 横書きハイフネーションで挿入した語の`wordVerticalBehaviors`も並列に保つ。Reader Test Viewはboolコールバックへ追従。

### 保証の範囲と残る制限

**これは事前検査によるOOM防御であり、全STL確保を失敗可能なAPIへ変換した実装ではない。** `vector::resize/assign/reserve`、stringコピー、shared_ptr制御ブロックは標準アロケータのまま。検査と実際の確保の間に別タスクがheapを使い切る場合や、見積もり外の内部確保まではabort回避を保証できない。nothrowのTextBlock本体と事前検査の失敗、コールバック拒否は安全に中断できるが、「どの確保点で実際にmallocが失敗しても絶対にabortしない」という要求は未達。

厳密な保証には所有領域を保持するfallibleコンテナ/アリーナとTextBlockの格納方式まで変更する必要があり、今回の最小差分から分離した課題とする。Expatの入力蓄積、フォント実装全体、画像変換、SectionのLUT拡張なども今回ですべてnothrow化したわけではない。

試行確保は各配列の合計を一つの連続領域として確認する保守的な方式。断片化時には個別配列なら収まる入力も中断し得る。1行/列のコピー分も一時的に必要になる。実機で通常書籍を過剰に拒否しないか、ログとheapを測って調整する。

OOM防御そのものは通常成功時の組版を変えない。一方、圏点の実機調査で、**外部CSSを持たないEPUBではインラインの`style`属性まで読み飛ばす**不具合を見つけた。外部CSSパーサーがない場合にも、書籍スタイルが有効ならインラインCSSを適用するよう修正した。圏点・字形・行列の予約領域が既存キャッシュに入らないため、版定数を`SECTION_FILE_VERSION = 114`へ上げた（このrepoでは`SECTION_CACHE_VERSION`という名前ではない）。禁則分類、CJK原文空白／改行、番号付きリスト、`sup/sub`、`pre`、見出し間隔で組版結果または保存形式も変わるため、最終的に`121`へ更新した。次回の本を開くと該当章のキャッシュは自動で作り直される。

## 2. ブート時リカバリー

### 実装した入口

POWERによる起動時に側面キーを同時に押したままにする。X3は左サイドキー（`BTN_UP`）だけを入口にする。X4は実機で側面キーの物理順とADC論理名が一致しない個体があるため、**POWER＋二つの側面キーのいずれか**を入口にする。InputManagerの起動直後の状態が安定する500ms間、両方を保持する。X4は電源ラッチの都合で起動理由が`Other`となる場合もあるため、その分類では入口を閉じない。設定によるキー交換・読書方向には依存しない。画面が出たら両方を離す。

SD初期化後、`HalSystem::checkPanic()`、`SETTINGS.loadFromFile()`、言語設定、外部FontManager、通常の`setupDisplayAndFonts()`、APP_STATE、RECENT_BOOKSより前で分岐する。`SdFirmwareUpdateActivity(..., true)`を既存のファーム選択・検査・確認・更新処理へ接続した。

### 最小初期化とトレードオフ

- 表示とrenderer、ActivityManagerの描画タスク、内蔵UI_10/UI_12/SMALLフォント、既定入力、Classicテーマを使用。日本語UIは内蔵の文字を使う。SDフォント探索、読書フォント、読書用フォント展開器の初期化を省略する。
- `setupDisplayAndFonts(true)`として共通化。**通常の全フォント初期化より前での分岐は必要だが、表示初期化自体より前にActivityを開くことはできない**。SD、画面、描画タスクが動作することは復旧画面の前提。
- ハードウェア検出・電源・RTC/傾きセンサーとSD初期化は従来順序のまま。ブートローダー、表示SDK、SDハードウェア自体の故障や初期化ハングを救う独立リカバリーパーティションではない。
- ファーム選択モードのFileBrowserが読書状態索引とキャッシュディレクトリを読んでいた箇所を迂回。キャンセル、無効な選択結果、更新失敗は復旧モード内のファーム選択へ戻す。
- 復旧中は通常のloopのスリープ/APP_STATE保存を通らない。POWERを1.5秒以上長押しすると状態保存なしで再起動する。更新処理中の同期書き込みでは通常loopへ戻らない。
- SD初期化失敗時も内蔵UIだけのエラー画面を表示し、POWER長押しで再起動可能にする。復旧を起動したPOWERと側面キーの両方が離れるまでファーム選択を始めない。現在のフォルダに`.bin`がない場合は、フォルダ一覧が存在していても「.bin ファイルがありません」と明示する。表示用ファイル名の文字範囲は内蔵UIフォントの範囲に制限される。
- ファーム検査と確認画面は既存方式を維持。確認見出しには現在の端末（X3/X4など）を表示する。defaultのC3ファームはX3/X4共通のため、これはbin内の対象機種を推定する表示ではなく、書き込みを確認している実機を示す。キー同時押しだけで書き込みを始めない。
