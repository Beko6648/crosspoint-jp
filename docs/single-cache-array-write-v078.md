# 単体生成: 座標・スタイル配列の一括書き込み候補

基点cf410104、SINGLE_CACHE_PROFILE診断を保持した比較候補。X3/X4で実機確認済み。一括生成のSDパス一覧の修正とは別チェックアウト。

## 計測根拠

X3 device-monitor-260927-115642.log: run 96055ms、満杯advance table 82593us、縦配置56350164us、ページ書き込み14717870us（869ページ）。これらは内包時間で単純合算できない。満杯時早期returnは効果が小さいため保留。ページ保存中はTextBlock::serializeがwordXpos/wordStyles/wordYposを1要素ずつwriteし、各回HALのStorageLockを取得する。

## 変更

既存vectorの連続データを、そのまま1回のwriteで保存。既存と同じ型・同じ要素順・同じnative byte orderであり、キャッシュ形式・版数は変更しない。バッファ確保を追加せず、保持メモリを増やさない。文字列・ルビ・その他の保存は変更しない。配列書き込み不足はfalseを返し、既存のSection側の保存失敗処理へ渡す。

テストは旧writePod反復と新writePodArrayのバイト一致を、空配列・負数/境界座標・uint8_t enumスタイル・2000要素で検証。短い書き込みとサイズ積算overflowの検出も検証。配列1本につきN回→1回（空なら0回）を確認。

縦書き配置の56秒には列生成のコールバックからのページ保存も入り得るため、ページ保存改善が縦配置計測値にも反映され得る。実測比較は下記参照。1回のSD writeが長くなるため中断応答も実機確認対象。

## X3比較手順

同じ本「元審神者が美の結晶に成り代わった件」、同じSDフォント・サイズ・向き。対象1冊のみキャッシュ削除。単体生成を開始し1〜2分で中断、ログ取得。前のprofile-v1と共通する完了章についてSCP page_write/verticalとSCT parse/buildを比較（中断章を除外）。その後、生成できたページの本文・ルビ・記号・画像表示を確認。比較は各1回の参考値とする。
