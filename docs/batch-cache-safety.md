# 全書籍キャッシュ生成 修正版v2

前のunique_ptr変更を含む通常版: yomuka-batch-cache-v2-default.bin。
診断版ではない。最初はX3だけで確認する。

## 変更
- 書籍変更時に進捗を更新。全体の25%刻みに加え、5秒経過した次の章開始時にも章番号を更新する。
- 長い章の解析中に5秒ごとの更新を保証するものではない。章開始時の更新条件であり、ページごとの描画は増やしていない。
- 一括生成では書籍のCSS解析前に不要なフォントキャッシュを解放する。
- CSS準備不足の本は未完了として次へ進む。各章でCSSを途中までしか読めない場合も、その章の一時ファイルを除去して本を未完了にする。
- CSSルールが空の本と書籍スタイル無効は通常どおり処理する。
- CSS抽出/列挙失敗やサイズ制限で一部を処理できなかった場合、不完全なCSSキャッシュを保存しない。
- 通常読書の外部CSS省略フォールバックは維持する。厳格なCSS読み込みは全書籍生成で指定する。

## X3での手順
1. 更新後、次のコマンドでログを開始。
2. 前回と同じ全書籍キャッシュ生成を開始。キャッシュは削除しない。
3. 前回止まって見えた本で1分ほど観察し、章番号が更新されるか確認する。
4. 中断できることを確認。余裕があれば再実行し、終了時の完了/再開可能/未生成の件数を控える。
5. Ctrl+Cでログ終了。画面の様子とともに報告する。

```powershell
cd C:\Src\crosspoint-jp
& 'C:\Users\pompo\.platformio\penv\Scripts\platformio.exe' device monitor --port COM4 --baud 115200 --filter log2file --filter send_on_enter
```

CSSが大きすぎてまだ収まらない本は、修正版でも未完了になり得る。目的は全ての本を無理に完了扱いすることではなく、スタイルを省略した新規章キャッシュの公開を防ぐこと。
CSS再構築に成功した場合、既存の仕組みでその本の章キャッシュを再生成するため、以前より処理時間が増える場合がある。

## 状態
v2ではX3のCSSメモリ不足を検出して安全に未完了とすることを確認。その後のv3でCSS保存をストリーミング化し、X3/X4とも生成・表示・再利用を確認済み（css-streaming-cache.md参照）。PXC6形式と章キャッシュ形式の変更なし。
以前からある章キャッシュにはCSS省略の印がないため、既存キャッシュ全てのスタイル完全性をこの修正だけで証明はできない。
