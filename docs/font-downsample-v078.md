# SDフォント縮小時の細線欠け

## 原因と変更

NotoSerifJp、文字サイズ「中」、`css-cache-mixed-v1.epub` の h2「中央の見出し」で、
太字「央」の上側の横棒が欠ける。手元の18pt太字データには横棒があるが、
16pt相当（scale=227/256）への最近傍縮小で、その行が選択されない。
37×38画素の字形では元の行8、17、26、35が抜ける。
他フォントでは欠けないことをユーザー確認済み。

`renderChar` の2bit字形の縮小のみ、画素の重なり面積で濃度を平均する。
整数演算で処理し、追加のヒープ確保はない。等倍・拡大・1bit字形・
独立した90度回転文字描画経路は変更しない。
字形寸法、配置、送り幅、章キャッシュ形式、SDフォントファイルは変えない。
変更は他のSDフォントの縮小にも適用される。

## 自動確認

`test/run_glyph_downsample_test.py --compiler <zig.exe>`:
全ての行・列に置いた細線、4段階の均一濃度、端の画素、等倍を確認。
実フォントを使った比較画像でも「央」の横棒が残ることを確認。
default / gh_release のビルド成功（67.034秒 / 68.858秒）。

## 実機確認（X3、次にX4）

キャッシュ削除やSDフォントの入れ替えは不要。ファーム書き込み後、
NotoSerifJp・サイズ「中」で同じ本を開く。

1. 「中央の見出し」の「央」の横棒が見えること。
2. 前後の本文、太字、ルビ、句読点、括弧に欠けや不自然な太さがないこと。
3. 横向きでも同じページを確認。通常のページ送りに目立つ遅延がないこと。
4. 欠けなかった別フォントでも同じ見出しを確認する。

不具合が出た場合はフォント・サイズ・向きと画面を記録する。
この確認は目視を中心とし、シリアルログは必須ではない。

## 実機結果（2026-09-27）

確認用ファーム `yomuka-font-downsample-v1.bin` で、X3・X4ともに
上記1〜4をユーザー確認済み。「央」の欠けが改善し、表示・操作感に問題なし。
シリアルログによる描画時間の定量比較は行っていない。
main統合は別途行う。
