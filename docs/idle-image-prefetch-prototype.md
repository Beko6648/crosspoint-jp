# 画像先読みとメモリ余裕判定

## 適用範囲

ブランチ feat/v0.7.8-idle-image-prefetch。基点8eff8b3c。上流#3675の調査時head 3ddb78fを参考にした限定実装。

- default / gh_release: idle先読みを有効化。詳細診断は無効。画像表示前の条件付きフォント解放も有効。
- debug: 比較用にidle先読みは無効のまま。
- idle_image_acceptance: defaultを継承する通常版相当の確認環境。
- idle_image_test: 同一章の次ページ画像の先読みを有効化。
- image_render_memory_test: 上記に加えてIRMの区間メモリ診断を有効化。
- PXC6形式、画像の配置・dither、Home縮小表紙、次章生成は変更しない。先読み中のFrameBufferLoanは使用しない。

## 処理

描画完了・最後の入力から1秒後、RenderLock下で描画世代を再確認し、同一章の次ページを読み込む。1回1画像、画像間も1秒待つ。総空き72KiB/最大連続20KiB未満なら見送る。入力・USBイベントを受けたら協調キャンセルし、取得した入力を通常loopへ引き渡す。部分キャッシュは破棄。失敗・中断した画像は同じ描画回で連続再試行しない。

先読みはフォントを解放しない。PNGはさらに本体sizeof(PNG)=58464、元幅ぶんのgray行、PXC行、32KiB余裕、4KiB見込みを合計して判定する。確保後にも36KiBを再確認。不足時は通常表示に任せる。

画像表示では本文・ステータスバー描画後、BW画面退避前に余裕を判定する。必要量の目安はframe+40KiB（読込み4KiB、見込み4KiB、余裕32KiB）、最大連続領域8192バイト。X3=93232、X4=88960バイト。不足時だけ字形キャッシュを解放し、なお不足する場合だけkern/ligature表も解放する。通常の確認付き画面退避・失敗処理は維持する。

これらはメモリ予約ではなく、断片化・他タスクの影響を含む安全保証ではない。入力pollの5msも最大中断遅延の保証ではない。

## 実機確認

ユーザー提供のX3/X4ログと目視確認による。フォントNotoSerifJp pt14、確認用英語・日本語EPUB。全方向・全フォント・全書籍の保証ではない。

- 日本語PNG: 余裕不足時に先読みを見送り、通常表示で生成成功。
- 英語PNG: 余裕判定版で両機種とも先読み成功を確認。
- JPEG: 先読み成功。中断後の部分cache破棄と通常描画での再生成も確認。
- 日本語の最初のJPEG: 字形のみの解放でX3は78044→116172、X4は85432→122092バイトへ回復。補助表までの解放はこの条件では不要。
- BW退避後の最大連続領域はX3=38900、X4=32756バイト。従来X3で発生した約4KB読込みから1行126バイトへのfallbackは修正版ログにない。
- 最初の画像表示後の起動後最低空き値はX3=46700、X4=49924バイト。これは瞬間の空き量とは別の指標。
- 英語版では追加の条件付き解放は全画像release=0。通常のcache miss decode経路には従来のフォント解放があるため、すべての経路で保持する意味ではない。
- 次の日本語本文はX3約2.82秒、X4約2.05秒。前回とほぼ同程度の単回測定で、広範な速度保証ではない。
- ユーザー目視: 文字・画像欠け、残像、通常読書の操作に問題なし。早めくりの軽い引っかかりは許容として現状採用。画像後のリフレッシュは維持。

対応ログ名: x3/x4-idle-ja-budget.txt、x3/x4-idle-en-budget.txt、x3/x4-image-render-memory.txt、x3/x4-image-headroom-ja.txt、x3/x4-image-headroom-en.txt。生ログはコミットしない。以前のx4-idle-ja-off.txt/on.txtはファイル名が逆だったことをユーザー確認済み。

## 診断とテスト

IRMは画像ページだけ固定64レコードにfree/maxAlloc/minFreeと採取時刻を記録し、描画終了後に出力。固定領域1536バイト＋管理情報。記録上限超過はdroppedで表示。既存ログ・他タスク・静的RAM増加の影響は残るため、診断版で操作全体の速度比較はしない。ログ行の欠落があり、dropped=0だけでは受信完備を保証しない。

ホストテスト:
- test/run_idle_image_test.py: 実HALのイベント保持、キャンセル、部分cache破棄・再生成、PNG判定。
- test/run_image_render_memory_test.py: 固定記録・タスク除外・上限・無効化、および画像表示budgetの境界値・段階的解放。
- 既存test/run_image_cache_test.pyとtest/run_decoder_loan_test.pyも作業中に成功。JPEGは56条件一致、既知のhost拒否8条件は両経路で一致。

default / gh_release / image_render_memory_testは実機配布前の8eff8b3c-dirty-47880a06でビルド成功。実機確認はこの試作ビルドで行った。コミット後のビルドは成果物ログで追跡する。

## 未解決・対象外

早めくり時の軽い引っかかりは既知。診断ログ、再読込み、画像後のrefreshの寄与は個別に断定しない。
X3日本語PNG①で1回3076msを観測。同一データPNG②は1078ms、以前は1067～1165ms。開始heap/MaxAllocは同じで、遅延中の省電力移行記録なし。SD I/O/タスク待ちの内訳は未計測。単発・原因未確定として追加修正しない。
混在ページ・長時間断片化・全方向/全フォントの組合せの網羅試験、PNGdecoder分割、次章incremental生成は未実施。

## 通常版への有効化

詳細診断を外したidle_image_acceptance（eb2361d7-dirty-12107467）をX3/X4最終確認用として配布。日本語画像前後、戻る/メニュー、早めくり、章移動・再開、代表ページの4方向とSDフォントなしの確認を依頼し、ユーザーから「OKでした」と回答を受領。今回ログは必須とせず目視・操作確認として扱う。通常版への有効化を承認された範囲で実施する。

default / gh_releaseに既存IDLE_IMAGE_PREFETCH_TESTフラグを追加。名称は歴史的なものだが、同一の先読みと入力引継ぎコードを有効化する機能スイッチとして使用する。実機確認後に実装の書き換えは行わない。debugはOFF比較用として維持。v0.7.8のタグ・リリース・pushはこの変更には含まない。
