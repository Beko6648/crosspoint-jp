# 読了位置のEPUB参照修正

## 問題と変更
読了画面は spineCount を位置として保持するが、有効な章番号は 0..spineCount-1。
目次変換と進捗計算がこの位置を getSpineItem に渡す経路があった。
X3/X4のCSS混在テストで index:4 の範囲外ログを確認したが、ログ単独では発生操作は特定できない。

- getTocIndexForSpineIndex: 範囲外は -1（目次画面の既存処理で先頭選択）。
- calculateProgress: 非空の本の読了位置以降は 100%、負の位置は 0%。空の本は既存の 0%。
- 通常章の計算とキャッシュ形式は変更なし。
- キャッシュ保存高速化とは別ファイルの変更。独立した変更として記録し、main統合は別途行う。

## 検証
実際の2メソッドを取り出し、範囲外参照を拒否するホストテストで検証。
通常章、目次項目なし、読了位置、過大/負の位置、空の本、1章の本を確認。

## 実機確認 X3 / X4
同じ CSS混在・キャッシュ保存確認v1 を使用。キャッシュ削除は不要。
1. 最終章の末尾から進み、読了画面へ。
2. メニューの進捗が100%であることを確認。目次を開き、第1章を選んで正常表示。
3. 再度読了画面へ進み、Homeへ戻って開き直す。表示と操作に異常がないことを確認。
4. ログに getSpineItem index:4 is out of range、クラッシュ、再起動がないことを確認。

実機結果（2026-09-27）: X3 125528ログで1〜4 OK、範囲外参照・クラッシュ・再起動なし。X4は125926ログが書き込み前の可能性があり判定から除外。修正版書き込み後の130418ログでは同エラー・クラッシュ・再起動なし。画面・操作1〜4 OKの申告と合わせて確認。単体/一括キャッシュの再生成は不要。

default / gh_release / single_cache_profileのビルド成功。ホスト境界テスト成功。ログ判定は記録範囲内に限る。
