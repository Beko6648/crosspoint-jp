# 一覧速度の確認 v1（まずX3）

> 2026-09-27: この文書は試験版ごとの経過を含みます。現在のmain統合・実機受入状況と継続調査は[v0.7.8リリース監査](development/v0.7.8-release-audit-ja.md)を参照してください。

目的は100／300／500冊の一覧走査、状態取得、画面更新を分けて測ることです。高速化の変更はまだありません。

## 準備
1. `yomuka-library-profile-v1.bin` を通常のSDファーム更新手順で適用します。
2. `library-profile-v1-books.zip` をPCで展開し、`library-profile-v1` フォルダごとSDカード直下へコピーします。
3. 既存の書籍キャッシュは削除しません。全書籍キャッシュ生成も行いません。
4. シリアルログを開始し、端末を一度再起動します。各冊数の間の再起動は不要です。

## 操作（books-100 → books-300 → books-500の順）
1. Homeからファイル一覧を開き、library-profile-v1、対象フォルダへ入ります。表示と状態アイコンが落ち着くまで待ちます。
2. 一覧を次のページへ進め、前のページへ戻ります。
3. 親フォルダへ1回戻り、同じフォルダへ入り直します。
4. そのフォルダの本を1冊開き、本文が表示されたらHomeへ戻ります。Homeの表示が落ち着くまで待ち、同じフォルダをもう一度開きます。
5. 待たされた操作、表示欠け、状態アイコンの不整合があれば記録します。

3種類を終えたらログを停止し、X3のログと目視結果を渡してください。まずX4で同じ試験を繰り返す必要はありません。

## ログ取得
PowerShellで以下を実行します。終了はCtrl+C。COM4が実機のポートと異なる場合は変更してください。

```powershell
cd C:\Src\crosspoint-jp
& 'C:\Users\pompo\.platformio\penv\Scripts\platformio.exe' device monitor --port COM4 --baud 115200 --filter log2file --filter send_on_enter
```

## 計測の読み方・制約
- FBPERF: フォルダのパス、cache hit/miss、走査、並べ替え、状態取得、描画、画面更新。
- LIBPERF: 一覧への入場、状態索引読み込み、一覧取得、退出、Homeの最近の本・表紙・描画。free/maxは処理境界、bootMinは起動全体の最小値です。
- 親子の時間は重複するため合算しません。診断ログ自身の出力時間も含まれます。
- 同じ一覧に留まる場合と、親へ戻る場合、Homeから入り直す場合は別の条件です。
- 128件を超えるフォルダを保持しない現在のメモリ保護は維持します。
- この試験は小さな未生成EPUB中心の基準測定です。大量の既存キャッシュや全生成後の状態索引の評価は別段階です。
- Homeの最近の本は操作によって変わります。比較時はその影響を区別します。
- 900冊を全生成する必要はありません。生成対象に混ぜたくない場合、試験後にこの専用フォルダをSDからPCへ移動できます。

## 2026-09-26 調査結果（X3）

基準はmainの77e8a504。専用library_profile環境にのみLIBPERFを追加し、通常版と同じ画像・次章先読みを有効にした。default / gh_release / library_profileのビルドが成功（67.678 / 66.437 / 85.511秒）。ELFでLIBPERFが専用環境だけに含まれることを確認。キャッシュ保持量、入力処理、表示仕様は変更していない。

### 確認用900冊

device-monitor-260926-212154.logで100／300／500冊の順に確認。ユーザーは手順1〜4で目視・体感の問題なしと報告。

| 冊数 | 一覧取得の目安 | 画面更新 |
|---|---|---|
| 100 | 約42ms | 約651〜660ms |
| 300 | 約130ms | 約651〜660ms |
| 500 | 約320ms | 約651〜660ms |

一部のシリアル行に欠落・連結があるため、欠けたフィールドを完全な測定値として扱わない。500冊はdirectory-loadの補助記録も参照。ファイル名は「一覧確認-001.epub」のような短い共通接頭辞と連番で、長く多様な日本語タイトルの再現ではない。ZIP内900冊の件数、XML解析、mimetypeの先頭・非圧縮配置、ZIP整合性をホストで確認した。外部EPUB適合性検査を行ったという意味ではない。

### 普段の読書用SDカード

device-monitor-260926-213649.logの486冊のフォルダで一覧取得276〜277ms、一覧部分描画78〜121ms、文字列正規化等815〜1776us、画面更新658〜659ms。初回は一覧取得276msと描画全体788msで約1.06秒。状態索引は46件、読み込み65ms。対象フォルダの追加キャッシュ状態取得は0件。ログにERR記録なし。ユーザーが申告した表示直後の一時的な操作待ちは再現しなかった。

確認用データとはSDカード、ファイル名、既存キャッシュ等の条件が異なる。描画時間差を日本語のみの影響と断定しない。境界の空きheapは途中ピークや入力遅延を証明しない。

### 保留・採否

- 現時点で一覧キャッシュの128件制限を引き上げる根拠はなく、維持する。
- FileBrowserのloop先頭は状態索引がdirtyの場合、RenderLockを取得して保存してからボタン処理へ進む。表示直後の待ちにつながる候補経路だが、今回の症状との因果は未確定。直接のボタン遅延計測も未実施。再現未確認として保留し、追加のキャッシュ消去や強制再現は求めない。
- X4はこの診断追加での実機確認を行っていない。X3結果をX4実測と扱わない。
- 1ページの本を通常読書で開いた後の半円は現行仕様。章キャッシュが存在しても、全書籍・本ごとの生成経路による完了markerがなければResumableになる。表示改善は別候補であり、今回は変更しない。
- この調査は速度改善や不具合修正の完了ではなく、診断と現状の基準値の記録である。

再生成コマンド: `py -3 scripts/make_library_profile_fixture.py <新規ZIPの出力先>`。既存出力の上書きは拒否する。シリアルログ、EPUB ZIP、ファーム本体はリポジトリへ含めない。
